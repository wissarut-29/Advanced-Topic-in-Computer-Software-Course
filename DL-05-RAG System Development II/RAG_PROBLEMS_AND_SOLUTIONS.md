# เอกสารวิเคราะห์ปัญหาและการแก้ไขปัญหาของ RAG System (DL-04 & DL-05)

เอกสารนี้รวบรวมการวิเคราะห์ **ปัญหาและการแก้ไขปัญหาของระบบ RAG (Retrieval-Augmented Generation)** ที่พัฒนาขึ้นจริงในโปรเจกต์ `DL-04-RAG System Development I` และเชื่อมโยงกับการจำลอง 9 สถานการณ์ปัญหาใน `DL-05-RAG System Development II` โดยแบ่งตามขั้นตอนการทำงานตั้งแต่ Input จนถึง Output

---

## รายละเอียดเชิงลึกแยกตามแต่ละปัญหา (Detailed Breakdown)

### ปัญหาที่ 1: การรับคำถาม & Vocabulary Mismatch (เชื่อมโยง DL-05 Problem 02)
* **สาเหตุ**: ผู้ใช้งานมักพิมพ์คำถามด้วยภาษาพูดหรือคำย่อ เช่น ถามว่า *"นิวรัลเน็ตคืออะไร"* หรือ *"ไฟน์จูนต่างจาก RAG ยังไง"* แต่ในคลังความรู้ถูกเขียนด้วยศัพท์ทางการว่า *"โครงข่ายประสาทเทียม"* หรือ *"Fine-tuning"* ส่งผลให้อัลกอริทึม Keyword Match (BM25) ไม่สามารถจับคู่คำได้เลย (Exact-token overlap = 0)
* **วิธีตรวจสอบ**: ทดสอบรัน `problem02_transformer.py` เพื่อดูค่า Bag-of-Words (BoW) ของประโยคทางการเทียบกับประโยคแสลง
* **การแก้ไขในระบบจริง**:
  - ในไฟล์ `src/query_transform.py` ฟังก์ชัน `normalize_query()` จะนำคำถามมาเทียบกับพจนานุกรม `SLANG_MAP` เพื่อแปลงคำย่อ/แสลงเป็นคำทางการก่อนนำไปสืบค้น
  - หากเปิด `USE_QUERY_TRANSFORM = True` ระบบจะส่งคำถามให้ LLM ช่วยคิดคำถามทางเลือก (Multi-Query) หรือแต่งคำตอบสมมติ (HyDE) ทำให้คลุมบริบทได้ครบถ้วน

---

### ปัญหาที่ 2: การตัดแบ่งข้อความและบริบทสูญหาย (เชื่อมโยง DL-05 Problem 04)
* **สาเหตุ**:
  - หากกำหนด `CHUNK_SIZE` ใหญ่เกินไป (เช่น > 1,000 ตัวอักษร) เวกเตอร์ของ Chunk จะมีความหมายเจือจาง และอาจล้นหน้าต่าง Context Window ของ LLM
  - หากกำหนด `CHUNK_SIZE` เล็กเกินไป ข้อมูลประโยคคำตอบจะถูกหั่นขาดตอน ทำให้ใจความสำคัญหายไป
* **วิธีตรวจสอบ**: รัน `problem04_chunking.py` หรือตรวจสอบไฟล์ `outputs/chunks.json` เพื่อดูการกระจายตัวของความยาวข้อความและตำแหน่งการตัดคำ
* **การแก้ไขในระบบจริง**:
  - ใน `config.py` กำหนดค่า `CHUNK_SIZE = 400` และ `CHUNK_OVERLAP = 50`
  - ใน `src/text_splitter.py` นำข้อความ Question และ Answer มารวมกันเป็น `full_text = f"Question: {record['question']} Answer: {record['answer']}"` ก่อนตัด เพื่อให้ทุกชิ้นส่วนรู้เสมอว่าตนเองตอบคำถามอะไรอยู่

---

### ปัญหาที่ 3: ข้อจำกัดของการค้นหาแบบเดี่ยว & การรวมคะแนน (เชื่อมโยง DL-05 Problem 06)
* **สาเหตุ**:
  - **Dense Search (FAISS)** เก่งเรื่องความหมายแฝง แต่แยกแยะคำเฉพาะเจาะจง (เช่น ชื่อรุ่นโมเดล หรือตัวย่อเฉพาะทาง) ได้ไม่ดี
  - **Sparse Search (BM25)** เก่งเรื่องคำเฉพาะเจาะจง แต่ไม่เข้าใจคำพ้องความหมาย
  - เอกสารที่มีคำทั่วไป (Generic Terms เช่น คำว่า "LLM", "ตรวจ") ซ้ำกันหลายจุด อาจได้คะแนนสูงกว่าเอกสารที่มีคำตอบเจาะจงจริง ๆ
* **วิธีตรวจสอบ**: รัน `problem06_reranking.py` หรือเปรียบเทียบผลลัพธ์ใน `eval_retrieval.py`
* **การแก้ไขในระบบจริง**:
  - ใน `src/hybrid_retriever.py` ดึงผลลัพธ์ทั้งสองฝั่ง (`dense_search` และ `bm25_search`) มารวมกันผ่านสูตร **Reciprocal Rank Fusion (RRF)**:
    $$\text{RRF Score} = \sum \frac{1}{k + \text{rank}}$$
  - นำผลลัพธ์ผู้เข้ารอบ `CANDIDATE_K = 20` ส่งต่อไปให้โมเดล Cross-Encoder ใน `src/rerankers.py` (`BAAI/bge-reranker-v2-m3`) ทำการ Rerank ใหม่ เพื่อดันเอกสารที่เฉพาะเจาะจงที่สุดขึ้นมาเป็นอันดับ 1

---

### ปัญหาที่ 4: การติดกับดักผลลัพธ์อันดับเดียว (`top_k = 1`) (ปัญหาที่เกิดขึ้นจริงใน DL-03)
* **สาเหตุ**: ในโค้ด `main.py` มีการกำหนด `top_k = 1` แบบ Hardcoded ทำให้เมื่อผู้ใช้ถามคำถามกว้าง ๆ ระบบจะหยิบเฉพาะเอกสารที่มีคำศัพท์ครอบคลุมสูงสุด (เช่น เรื่อง Parameter ใน LLM) มาแสดงผลเพียงชิ้นเดียว ปิดกั้นเอกสารอื่น ๆ ที่ผู้ใช้อยากรู้
* **วิธีตรวจสอบ**: ทดสอบถามคำถาม 2-3 ข้อที่แตกต่างกัน แล้วพบว่าระบบแสดงคำตอบเดียวกันตลอดเวลา
* **การแก้ไขในระบบจริง**:
  - แก้ไขใน `main.py` บรรทัดที่ 61 ให้เรียกใช้ `top_k = config.TOP_K` (คืนค่า 3 อันดับแรก)
  - ปลดคอมเมนต์แสดง `Category` และ `Similar Question` เพื่อให้ผู้ใช้ตรวจสอบได้ว่าระบบอ้างอิงมาจากคำถามใด

### ปัญหาที่ 5: โมเดลประสาทหลอนและการบิดเบือนข้อมูล (เชื่อมโยง DL-05 Problem 01 & 07)
* **สาเหตุ**:
  - **Hallucination**: ผู้ใช้ถามคำถามที่อยู่นอกขอบเขตคลังความรู้ (Out-of-KB Scope) แต่ LLM พยายามแต่งคำตอบขึ้นมาเองจากความจำเดิม
  - **Unfaithfulness**: LLM สรุปข้อมูลแล้วเปลี่ยนตัวเลขสำคัญ เช่น ระยะเวลา 72 ชั่วโมง กลายเป็น 7 วัน
* **วิธีตรวจสอบ**: รัน `problem01_hallucination.py` และ `problem07_generation.py`
* **การแก้ไขในระบบจริง**:
  - ใน `src/prompt_templates.py` กำหนด `SYSTEM_PROMPT` เข้มงวด:
    > *"ใช้เฉพาะข้อมูลใน 'ข้อมูลอ้างอิง' ห้ามเพิ่มความรู้จากภายนอก ถ้าข้อมูลไม่พอให้ตอบว่า '{no_context}' ห้ามเดา และต้องใส่อ้างอิง [1] [2]"*
  - ใน `src/generator.py` มีระบบดักจับ `if not chunks: return {"answer": config.NO_CONTEXT_MESSAGE}` ทันทีเพื่อป้องกันไม่ให้ส่งพรอมต์เปล่าไปหา LLM

### ปัญหาที่ 6: การประเมินผลและการสุ่มชุด Golden Set (เชื่อมโยง DL-05 Problem 09)
* **สาเหตุ**: เมื่อเปลี่ยนชุดข้อมูลมาเป็นเรื่อง Deep Learning & LLMs ที่มีขนาดกะทัดรัด (22 คู่คำถาม-ตอบ) การตั้งค่า `GOLDEN_SET_SIZE = 60` ทำให้ฟังก์ชันสร้างข้อสอบพยายามดึงข้อมูลเกินขนาดคลังข้อมูลจริง
* **วิธีตรวจสอบ**: รัน `python -m evaluation.build_golden_set` แล้วเกิดข้อผิดพลาดในการกระจายข้อมูลตามหมวดหมู่
* **การแก้ไขในระบบจริง**:
  - ปรับค่า `GOLDEN_SET_SIZE = 20` ใน `config.py`
  - สร้างชุดคำถามทดสอบ 4 รูปแบบ: `verbatim` (คำถามเดิม), `slang` (คำถามภาษาพูด), `partial` (คีย์เวิร์ดสั้น), และ `natural` (คำถามธรรมชาติ) เพื่อวัดค่า Hit@k, MRR และ nDCG ได้อย่างสมจริง
